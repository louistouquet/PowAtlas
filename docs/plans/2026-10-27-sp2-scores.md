# SP2 — Tableau public des scores : plan de mise en œuvre

> **Pour les agents :** sous-skill requis : `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans`, tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`) pour le suivi.

**But :** publier chaque jour sur `PowAtlas/scores` les scores de la neige fraîche des modèles bruts, d'abord sur l'historique rattrapé, puis sur la saison 2026-27, calculés par GitHub Actions à partir de `PowAtlas/archive`.

**Architecture :** le paquet `powatlas` gagne quatre modules :
- `hub` : envoi vers Hugging Face, unité par unité, comparaison des manifestes ;
- `quot` : lecture de la base quotidienne de Météo-France ;
- `pairs` : extraction, cumuls, neige directe ou dérivée, conversions, Parquet ;
- `scores` : mesures, climatologie, rééchantillonnage apparié, CSV.

`collect.yml` envoie les unités complètes ; le PC envoie le reste (`powatlas publish`) ; `scores.yml` calcule et publie.

**Pile :** Python 3.12 (3.14 sur le PC du pilote), `numpy`, `netCDF4`, `huggingface_hub==2.2.0` (publié le 2026-10-08, Trusted Publishers depuis 1.19), `pyarrow==26.0.0` (publié le 2026-10-09, roue Windows cp314 vérifiée le 2026-10-27) ; `unittest` ; GitHub Actions.

**Cadrage :** [`docs/specs/2026-10-27-sp2-scores-design.md`](../specs/2026-10-27-sp2-scores-design.md), à lire avec ce plan ; [décision 0007](../decisions/0007-hugging-face-au-centre-github-d-abord.md).

## Contraintes globales

- Zéro euro ; aucun compte créé par Claude ; jetons hors du dépôt (`HF_TOKEN` dans `.env` sur le PC, aucun secret Hugging Face dans GitHub : Trusted Publishers).
- **Aucune donnée dans Git** ; les fiches des jeux (`README.md` de Hugging Face) sont des métadonnées de moins de 100 Ko.
- **Rien n'est envoyé sur Hugging Face avant la tâche 1** (licences vérifiées et datées).
- Protocole de la section 4 du cadrage **figé** : densité fixe de 100 kg/m³ (officielle) ; Hedstrom-Pomeroy ρ = 67,92 + 51,25·exp(T/2,59) avec T plafonnée à 0 °C (sensibilité) ; seuil dérivé de 1,0 °C ; seuils de 1, 5, 10, 20 et 30 cm (≥) ; blocs de 7 jours sans chevauchement depuis le 1er novembre ; 2 000 tirages ; graine `20261027` ; intervalle à 95 % par percentiles ; climatologie sur les hivers 1996-97 à 2020-21 ; codes `QHNEIGEF` 0 et 1 officiels, 9 provisoire.
- Fenêtres : `HNEIGEF(J)` contre le run 00 UTC de J, de +6 à +30 h (48 h : +6 à +54 h ; 72 h : +6 à +78 h) ; Arpa `hn(D)` contre le run 00 UTC de D-1, de +7 à +31 h, sauf décalage établi par la tâche 9.
- Unités lues dans `GRIB_units` : `m` ou `m of water equivalent` → × 1000 ; `kg m**-2` → × 1 ; toute autre unité est une erreur.
- Hiver : novembre à avril.
- Code, commentaires, CLI en anglais ; documents en français ; skill `scientific-coding` pour les tâches 6 à 11 ; relecture `relecteur-scientifique` pour elles.
- Tests sans réseau ; aucune donnée tierce en fixture (NetCDF et CSV fabriqués dans les tests).
- Une PR par groupe ci-dessous ; CI `docs`, `python` et `windows` vertes ; relecture par un agent ; fusion en un seul commit.

## Points de vigilance

Les cinq modes de défaillance les plus probables que les tests nominaux ne couvrent pas, chacun épinglé par un test dans la tâche indiquée :

1. **Envoi interrompu** (PC éteint, quota de commits) : une unité n'est jamais à moitié publiée. Ses fichiers et son manifeste vont dans le même commit, et le manifeste distant n'est comparé qu'après (tâche 2, `test_unit_files_and_manifest_in_one_commit`).
2. **Unités mélangées** : un run IFS d'avant le 2025-11-22 n'a pas `sf`, un run d'après l'a. La règle choisie dépend de la présence de `sf` dans le fichier, jamais de la date (tâche 7, `test_ifs_without_sf_uses_derived_rule`).
3. **Unités `GRIB_units`** : l'AIFS en kg m-2, l'IFS en m. Une unité inconnue lève une erreur au lieu de produire un nombre (tâche 7, `test_unknown_units_raise`).
4. **Pas manquants dans la fenêtre** : un seul pas absent rend la paire `None`, jamais une somme partielle (tâche 7, `test_window_with_missing_step_is_none`).
5. **Fichier CSV de Météo-France** : décimales avec virgule, valeurs vides, codes absents. Une valeur vide n'est pas un zéro (tâche 6, `test_empty_value_is_none_not_zero`).

## PR 4 — Paires

### Tâche 7 : module `pairs` et commande `pairs`

**Files:** Create `src/powatlas/pairs.py`, `tests/test_pairs.py` ; Modify `cli.py`.

**Interfaces :**
- `SnowSeries(steps: np.ndarray, incr_mm: np.ndarray, t2m_c: np.ndarray | None, lats: np.ndarray, lons: np.ndarray, product: str)` : incréments de neige en mm par pas (axes pas, lat, lon) ; `product` vaut `direct` ou `derived` ;
- `load_snow(nc_path: Path, source_id: str) -> SnowSeries` :
  - règle directe si la variable de neige du modèle est présente (`sf`, `lsfwe`+`csfwe`, `tsnowp`) ;
  - sinon règle dérivée (`tp` ou `apcp` quand `2t` ≤ 1,0 °C en fin de pas) ;
  - cumuls convertis en incréments ;
  - unités par `GRIB_units` ;
- `nearest(lats, lons, lat: float, lon: float) -> tuple[int, int, float]` : indices et distance en km (haversine, R = 6371 km) ;
- `hp_density(t_c: np.ndarray) -> np.ndarray` : formule figée, T plafonnée à 0 °C ;
- `window_cm(s: SnowSeries, j: int, i: int, start_h: int, end_h: int, density: str) -> float | None` : `density` vaut `fixed` (1 mm → 1 cm) ou `hp` (mm × 1000 / ρ / 10) ;
- `Pair` : `season, model, product, network, station, alt_m, dist_km, day, run, window, obs_cm, obs_code, fc_cm_fixed, fc_cm_hp` ;
- `build_pairs(forecasts: list[Path], obs: list[Obs], windows=("24h", "48h", "72h")) -> list[Pair]` ;
- `write_pairs(pairs, path: Path)` : Parquet avec `pyarrow` ;
- CLI : `powatlas pairs --archive DIR --out DIR [--season 2025-26]`.
