# SP1 — Archive et observations : plan de mise en œuvre

> **Pour les agents :** sous-skill requis : `superpowers:subagent-driven-development` (recommandé) ou `superpowers:executing-plans`, tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`) pour le suivi.

**But :** mettre en service avant le 1er novembre 2026 la collecte quotidienne du cœur de score (GitHub Actions), son rapatriement sur le PC du pilote, puis le rattrapage historique et la priorité 2.

**Architecture :** un paquet Python `powatlas` (catalogue déclaratif, un adaptateur par famille de sources, écriture NetCDF et manifestes) ; un workflow `collect.yml` en trois jobs (`plan` → `collect` en matrice d'unités → `report`) dont l'état est porté par le nom des artefacts ; sur le PC, `sync`, `status` et `backfill`.

**Pile :** Python 3.12, `numpy`, `eccodes` (roues avec bibliothèque intégrée, 2.50 vérifiée le 2026-10-22), `netCDF4`, `requests` ; `unittest` ; GitHub Actions (`actions/upload-artifact@v4`).

**Cadrage :** [`docs/specs/2026-10-22-sp1-archive-design.md`](../specs/2026-10-22-sp1-archive-design.md) — à lire avec ce plan ; décision [0005](../decisions/0005-collecte-hybride-actions-et-pc.md).

## Contraintes globales

- Zéro euro ; aucun compte créé par Claude (le pilote crée le jeton GitHub de la tâche 17).
- **Aucune donnée dans Git**, aucun lien signé, aucun jeton ; tests d'accès réels de 50 Mo au plus ; seules des métadonnées de moins de 100 Ko sont commitées.
- Emprise : ouest 5,0, sud 43,5, est 7,9, nord 46,5 (WGS84), découpée avec **une marge de 2 mailles de la source**.
- **SP1 archive, il n'interprète pas** : unités et cumuls du producteur, aucune variable dérivée.
- Valeurs en float32, NetCDF4 zlib avec *shuffle* ; observations brutes telles que reçues, compressées.
- Chaque fichier lu garde son `Last-Modified` producteur ; chaque unité a un manifeste (sha256, taille, état, mode, flux, heures, URL, champs absents).
- Artefacts gardés **30 jours** ; nom `<source>__<AAAAMMJJTHHZ>__<état>` (prévisions) ou `<source>__<AAAAMMJJ>__<état>` (observations), états `complete`, `partial`, `missing` (équivalents anglais des états `complete`, `partielle`, `manquante` du cadrage, le code étant en anglais).
- Permissions du workflow : `contents: read`, `actions: read`, `issues: write`.
- Code, commentaires, CLI en anglais ; documents en français ; skill `scientific-coding` pour les tâches 2, 3, 6, 13, 15, 19.
- Tests unitaires sans réseau ; aucune donnée tierce en fixture (GRIB fabriqués par `eccodes`, index synthétiques).
- Une PR par groupe ci-dessous, depuis la branche de la session ; CI `docs` et `python` vertes ; relecture par un agent ; fusion en un seul commit.

## Points de vigilance

Les cinq modes de défaillance les plus probables que les tests nominaux ne couvrent pas, chacun épinglé par un test dans la tâche indiquée :

1. **Le dossier `00/` d'ICON contient encore le run de la veille** à 02:35 : les champs de la veille sont rejetés et l'unité est `partial`, jamais `complete` (tâche 9, `test_stale_previous_day_files_make_unit_partial`).
2. **Un proxy renvoie 200 et le fichier entier à une requête par plage** : le client découpe la plage demandée ou lève une erreur, jamais il ne renvoie le fichier entier comme s'il s'agissait de la plage (tâche 5, `test_range_answered_with_full_body_is_sliced`).
3. **Deux déclenchements se chevauchent** (retard de GitHub) : groupe de concurrence par tâche dans le workflow, et `plan` ne relance jamais une unité déjà `complete` (tâche 7, `test_plan_skips_complete_units` ; tâche 10, contrôle du YAML).
4. **Passage d'année** : du 1er au 7 janvier, les fichiers nivo-météo de l'année précédente et de l'année nouvelle sont copiés, un 404 sur le fichier de l'année nouvelle n'est pas un manque ; le nom de saison de la base quotidienne est découvert par listing (tâche 11, `test_new_year_collects_both_nivo_files` et `test_quot_season_name_discovered_from_listing`).
5. **Rapatriement interrompu ou zip corrompu sur le PC** : rien n'est écrit dans `data/` hors d'un déplacement atomique après vérification sha256, et l'artefact est retenté au passage suivant (tâche 16, `test_corrupt_artifact_leaves_archive_untouched`).
